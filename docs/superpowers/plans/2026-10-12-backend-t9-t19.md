# Backend implementation plan: T9–T19

**Goal:** Complete the remaining core backend phases in `docs/backend/06-implementation-tasks.md`, preserving the three NestJS service boundaries and the API/schema/error/message contracts in `docs/backend/`.

**Phase rule:** Implement one phase at a time with tests first. Run focused unit/integration coverage, `npx tsc --noEmit`, `npm test`, and `npm run build` as relevant; run `bash scripts/db/test-db` for database behavior. Have a separate reviewer check the NestJS module boundaries and contract coverage before each phase commit. Commit each finished phase separately with a conventional commit. Update the handoff only with checks actually run.

## Ordered work

1. **T8 exit evidence:** Run the existing candidate query with representative scale and capture `EXPLAIN (ANALYZE, BUFFERS)`; record the result and any actionable index/query change before treating T8 as closed.
2. **T9 Response missions:** Add a dedicated `missions/` feature module. Implement mission offer, member/leader reads, accept/decline/transition, coordinator record-on-behalf, cancel/fail, progress and readiness updates, overdue offers, notices, and mission-owned evidence. Cover transaction races and round-2 cases; use the approved verification snapshot when a supplement review is pending.
3. **T10 Response campaigns/map/reports/notices:** Keep lifecycle, public projection, internal campaign lookup, scoped heatmap/report, and notice inbox/read concerns in focused feature services/controllers. Validate geometry/projection and scale against the documented budgets.
4. **T11 Logistics catalog/assets/opening/adjustments:** Add focused modules for catalog and facilities, preserving the append-only stock movement trigger as the sole balance writer; require independent adjustment review.
5. **T12 Logistics drives/declarations:** Implement public drive projection, lifecycle, guest/signed declarations, revisions, disputes, claim, assisted declaration, and capability handling.
6. **T13 Logistics count/review/post:** Implement immutable count revisions, independent review, held-release/dispute paths, and exactly-once posting; exercise concurrent post and replay.
7. **T14 Logistics needs/commitments/fulfillment:** Implement cycle/need/commitment lifecycle, scope checks, fulfillment reads, and request-owned internal reads; exercise the documented commitment race.
8. **T15 Logistics distribution/handoff:** Implement the approved basic point handoff and settlement slice, with arithmetic, stock locking, and stale-approval protections. Keep explicitly deferred warehouse features out.
9. **T16 Resolution/cancellation seal:** After T9/T14/T15, implement durable Response intents and the Logistics seal fence, recovery, abort/adopt/finalize behavior, and crash/race tests. Preserve original `202` idempotent replay.
10. **T17 Reports/reconciliation:** Add scoped read models and discrepancy flags without mutating operational ledgers.
11. **T18 Hardening/evidence:** Verify response headers, throttling, log redaction, Vietnamese error accessibility, and recorded performance. Execute backup/restore only with the selected object-store artifact and documented key/checksum manifest available.
12. **T19 contracts/handoff:** Export and validate the per-service OpenAPI snapshots, update traceability/evidence and the backend handoff, and list acceptance checks that remain external or unrun.

## Boundaries

- No new dependency, service, migration/schema change, or API behavior is assumed without a documented contract requirement.
- Use `docs/backend/03-response-api.md`, `04-logistics-api.md`, `05-permissions.md`, `schema/*.sql`, and plan §28 as the implementation authority; later round-2 decisions supersede older conflicting prose.
- Keep retention unset until policy is approved. Do not add AI dispatch, push delivery, full offline, CSV export, multi-warehouse transfer, FEFO, formal stocktake, multi-leg forwarding, or the optional carrier slice.
- Keep `.codegraph/` user data untracked and out of commits.
